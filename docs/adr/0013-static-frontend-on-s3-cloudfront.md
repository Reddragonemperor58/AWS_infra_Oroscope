# ADR 0013: Static frontend on S3 + CloudFront, API CORS locked to the CloudFront origin

## Status
Accepted. Closes the CORS gap recorded in ADR 0009.

## Context
The backend (Cognito + API Gateway + Lambda + Aurora + S3 images) was verified only by scripts. The
clinic needs a page a doctor can use: log in, add a patient, enter clinical findings, run the
lookup, upload two photos, read the score. The cost target is near $0 at rest, and until now API
CORS `allow_origins` was `*` because no frontend origin existed.

## Decision
- **Static site, no framework, no build step.** Plain HTML + ES modules (`index.html`, `auth.js`,
  `api.js`, `app.js`, `style.css`) in `frontend/`. The page is a form wizard, so a framework adds
  tooling and supply-chain surface without removing any code. The only third-party file is the
  Cognito SDK, vendored in `frontend/vendor/` with its licence (no CDN script, so CSP can stay `'self'`).
- **Hosting:** private S3 bucket (public access blocked, SSE) behind CloudFront. Access uses
  **Origin Access Control**: the bucket policy allows only `cloudfront.amazonaws.com` with
  `AWS:SourceArn` equal to this distribution. Default `*.cloudfront.net` certificate; no custom domain yet.
- **Deploy = `terraform apply`.** `aws_s3_object` with `for_each = fileset("../frontend", "**")`
  uploads every file with a mime type and `Cache-Control: no-cache`. The distribution uses the
  managed CachingDisabled policy, so a deploy is visible on the next load and needs no invalidation.
- **Runtime config generated by Terraform.** `config.js` (API URL, region, user pool id, client id)
  is rendered from Terraform outputs, so the page never has hand-copied ids. None of these is secret.
  Do not create a `config.js` in `frontend/`.
- **Login:** Cognito SRP in the browser against the public app client (no client secret). Tokens live
  in memory only (not localStorage), so XSS cannot read them later and a reload logs the user out.
  The ID token is sent to API Gateway, whose JWT authorizer validates it.
- **Security headers** from a CloudFront response-headers policy: CSP (`default-src 'self'`,
  `script-src 'self'`, `style-src 'self'`, `img-src 'self' blob: data:`, `connect-src` limited to Cognito
  idp, API Gateway and S3 in ap-south-2, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`,
  `form-action 'self'`), HSTS, nosniff, X-Frame-Options DENY, no-referrer. The UI builds DOM with
  `createElement`/`textContent` (never `innerHTML`) and uses no inline script or style, so the strict policy holds.
- **CORS locked.** API Gateway `allow_origins` is now exactly `https://<distribution domain>`. The
  images bucket got a CORS rule allowing POST from that origin only (browser presigned upload).
- **Form behaviour.** The nine clinical fields use dropdowns, except Symptoms, Habits and Oral mapping,
  which are checkbox groups. Two or more ticks are sent as the single value the rules table uses
  (`Multiple symptoms`, `Multiple habits`, `Multiple areas`); the "none" values are mutually exclusive
  with everything else. Image 1 is the red-light photo, image 2 the blue-light photo.
  Re-submitting the findings creates a new diagnosis and replaces steps 2-3 on the page.

## Consequences
- Cost: S3 + CloudFront stay inside the permanent free tiers at prototype volume.
- The CloudFront domain is the only allowed origin. Adding a custom domain later means changing
  `allow_origins`, the images-bucket CORS and the CSP in one `terraform apply`.
- No server-side rendering or SEO; irrelevant for a logged-in clinical tool.
- A reload logs the doctor out (no token persistence). Silent refresh via the refresh token is a
  possible later improvement, weighed against the XSS exposure of storing it.
- Verified in a real browser: login, patient create, clinical lookup (single and multi-select), upload
  through S3 CORS, and score.
- Open: the "Multiple ..." collapse rule is inferred from the rules table values; confirm it matches the
  original app's behaviour.
- Open: the 7 scored diagnoses with no `clinical_rules` rows can be chosen in the dropdown and give
  "no rule matches" on lookup.
